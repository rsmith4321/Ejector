# Local 1.6.4: restore the eject choice for cameras with multiple storage sources

The 1.6.3 guard suppressed the completion dialog whenever another whole disk on the same USB device was mounted. This left an empty Internal scan with a notification and no eject selector, even though the user explicitly requested the dialog.

The completion flow now snapshots all mounted volumes on the nearest USB device and displays their names in a Keep Connected-default dialog. It states that only the completed source was checked and other storage may contain unimported media. Eject All Camera Storage flushes and unmounts each approved volume sequentially using FileManager without a hardware-eject command; this avoids disconnecting one logical disk while another is still mounted. Safe-to-unplug success requires every approved volume to be absent while the original USB device remains connected. UUIDs, disk identities, exact mounted set and connection tokens are rechecked; a busy disk, changed topology, disconnect/reconnect, or failed unmount stops the sequence with a partial-completion warning. No force unmount, copy or deletion is performed by this action. An explicit pending import-window Eject Now action opens this grouped confirmation too. Generic menu single-source eject retains the protective 1.6.3 guard.

Verified: Website archive/export and Store compilation; single-source signed disposable import/dialog/eject integration; native prompt labels/defaults; sequential success, failure, topology-change and final-validation regressions; actual two-volume disposable-image unmount; read-only live camera plan limited to Internal + SD Card. Installed native app displayed the grouped dialog on the actual camera and was left open for the user to choose. Actual-camera grouped eject was not performed.

Installed locally as Developer ID signed 1.6.4, with 1.6.3 and saved profiles backed up. No profile changes, new notarization, public release, website update, or Apple submission.
