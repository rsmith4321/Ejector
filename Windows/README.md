# Easy Eject for Windows · prototype 0.1

Native C# / Windows Forms source for Windows 11 x64, using .NET Framework 4.8 and supported Windows storage/PnP APIs. This implementation is isolated from the Mac targets and website. The current prototype passes 127 fixture/policy tests, native read-only enumeration, and a hidden-window notification smoke check. Real card/removal compatibility and visual UI acceptance are pending. See [PROGRESS.md](PROGRESS.md) for exact evidence and [PARITY.md](PARITY.md) for the full-project parity scope and direct-download plan. The exact camera model, reader and destination remain to be confirmed; this is not a complete port yet.

## Build and run

From the repository root in PowerShell:

```powershell
./Windows/build.ps1
./Windows/inspect-readonly.ps1
```

The build uses the installed `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, compiles app and test executable with `/warnaserror+ /platform:x64`, and places binaries/configuration under `%LOCALAPPDATA%\EasyEject\PrototypeBuild`, outside the OneDrive checkout. No SDK, NuGet download, installer, elevation, or startup registration is involved. A modern SDK project can be added later; this first slice uses the compiler already available on this laptop.

Only in an environment where execution is permitted by the existing security policy:

```powershell
./Windows/build.ps1 -Test
& "$env:LOCALAPPDATA/EasyEject/PrototypeBuild/EasyEject.Tests.exe" --inventory
& "$env:LOCALAPPDATA/EasyEject/PrototypeBuild/EasyEject.Tests.exe" --ui-smoke
& "$env:LOCALAPPDATA/EasyEject/PrototypeBuild/EasyEject.Tests.exe" --ui-render
& "$env:LOCALAPPDATA/EasyEject/PrototypeBuild/EasyEject.Windows.exe"
```

`-Test` runs 127 cases. They use fake discovery/removal adapters and disposable files under `%USERPROFILE%\.codex\EasyEjectFixtures\run-<id>`. Source and destination fixture directories share the host disk while the fake guard supplies two conceptual disk identities. Production imports always require different physical disks. Junction tests create junctions only within that fixture and do not change OS permissions. A configuration test writes/removes its own randomly identified fixture profile in the app's configuration storage. Default tests never invoke `CM_Request_Device_Eject`. `--inventory` reads native storage inventory, without a notification window or device operations. `--ui-smoke` constructs a hidden device window, registers disk and per-instance notifications with real shortcuts disabled, reads inventory and verifies system-eject policy; it briefly creates/disposes its tray icon but does not show a window or operate on devices. The separate PowerShell diagnostic uses OS CIM providers.

Smart App Control initially blocked an unsigned compiler probe. Ryan subsequently turned it off himself, after reviewing Microsoft instructions, and authorized continued testing. Ordinary executable launches now work. The agent did not change security policy, modify allowlists, install a trusted root, or use an alternate loader. Microsoft documents trusted code signing as the supported path for distributing an app with Smart App Control enabled; no signing account or credentials were used here.

## Use after runtime acceptance

The app opens a device window and adds a tray icon. Close hides the window; the tray's Quit exits when no operation is active. A session mutex prevents duplicate instances. Close also hides during an operation; tray Quit stays blocked until work and dialogs finish. Refresh performs read-only inventory. Device notifications refresh the list and invalidate pending actions. Connections never start import or eject automatically.

Select a device and choose **Safe eject…**. The confirmation names every known volume under the selected removal target, including sibling partitions and LUNs. No is the default. The service reserves affected physical disks, re-enumerates and compares identities/topology/connection generation, and requests Windows safe removal. Windows veto type, veto name, and CONFIGRET failures are shown without forced removal, retries, permissions changes, or broad hub ejection. Do not unplug after a failure.

The list groups camera candidates, emulator candidates, other external volumes, internal and protected Windows storage. Camera-folder evidence uses the eleven baseline root names. Emulator evidence needs two supported folders plus SD hardware; fixed/system storage and links never qualify. Generic NVMe with camera folders is only an unconfirmed camera candidate, never certified CFexpress. Card counts deduplicate partitions/LUNs under one removal device.

**Eject cards…** in the window/tray reviews all connected camera/emulator groups; Enter/Escape keeps them connected. Mixed/unclassified siblings and unknown/protected storage block the batch. The service reserves every confirmed disk first, removes one group at a time, verifies it absent, and stops on failure or changed peers. Earlier verified successes remain listed. New cards are never added to an old confirmation. Per-instance notifications preserve unchanged peers across the batch's own removals and reject identical reconnects. Missing/faulted tracking blocks bulk removal; individually confirmed removal remains available with its ordinary connection guard.

Settings offer an optional **Ctrl + Alt + Shift + letter** shortcut, off initially, default E, with D/E/F/G/K/M/R/T/X choices. It opens the same fresh confirmation. Only the chosen key is registered; auto-repeat, busy operations/dialogs and stale queued messages are suppressed. Conflicts are reported without registering a fallback key. Settings, shortcut and menu actions install no startup behavior. Native hotkey delivery and real multi-card removal are still pending acceptance.

Profiles normally live under local app-data. When launched by Codex's packaged host, Windows redirects the app's own configuration folder into that host's LocalCache. The profile store resolves this folder within local app-data and pins its canonical path. Source/destination media paths still reject redirection and all reparse points; there is no import-path exception for host virtualization.

Use **Import profile…** to choose a complete media folder or camera package on the selected volume and an existing destination on a different physical disk. Profiles offer **Use defaults / Use custom settings**, **Videos only**, **Include camera previews**, **Clean folder layout**, and **Ask to eject after import**. Inherited choices are visible and disabled until custom settings is selected. Save validates paths/device identity and never starts copying. **Import defaults…** changes media/preview/layout/completion choices for future imports using defaults; new profiles initially select Videos only with previews and clean layout, with eject prompting off. Earlier prototype profiles remain custom all-media with previews and preserved paths unless explicitly switched. Forget profile removes only its saved choices after confirmation.

**Verified import…** uses the saved folders and freezes current choices, explains the selection and both paths, then asks before copying with No as the default. If no valid profile exists, setup comes first, followed by a separate import confirmation. Formatting or a changed identity requires setup again. Invalid saved settings are explained rather than preventing folder setup. Imports keep originals and leave the device connected.

Each nonempty import uses a shared `YYYY-MM-DD` folder. Clean layout flattens ordinary media groups; whole conflict groups go under stable `Additional media/<fingerprint>` paths. Packages and unfamiliar files retain their selected folder/tree under `Camera originals/<fingerprint>`. Every import writes its own `.easy-eject-receipts/<id>/verified-import.json` and flushed `import-audit.log`. All-media selection copies regular files including unfamiliar extensions; Videos only uses conservative video/companion selection, protecting same-name still/movie pairs. Windows system-volume information and Recycle Bin folders are excluded. Partial camera-package selections are rejected; choose the complete package. Empty directories are not reproduced. This is verified file copying, not media conversion or universal camera-package certification.

The copy engine applies frozen videos/all-media and preview choices from the profile/default UI, with baseline still/movie, companion, proxy and structured-package rules. Seven file fixtures cover selection/package behavior; six further checks cover defaults/profile migration and frozen operation choices. Device indexes are backed up separately under `.easy-eject-metadata`, retained on source and distinguished from selected media in result/receipt. Matching saved files are SHA-256 verified and flushed before reuse; read-only saved files fail reuse safely. New files preserve camera modification dates and need free space greater than file size plus 1 GiB. Persistent last-20 history records exact saved files and destination identity. The other shared import options remain pending; see the full parity checklist.

Files are opened without following reparse points. Directory handles pin path components; source file handles deny concurrent write/delete. The importer checks source stamps, copies to exclusive private files with write-through/flush, hashes source and destination with SHA-256, re-reads source, and renames the held verified destination handle without replacing an existing file. It checks the whole source manifest and re-hashes all final copies/sources before publishing the completion receipt. Cancellation/failure retains originals and already published copies, removes only the held unpublished private file, and does not mark the batch complete. Flush errors fail the operation; this does not prove a drive's power-loss behavior.

## Conservative limits and differences from Mac

**Ask to eject after import** starts off. When enabled, completed imports appear in **Completed imports…** in the window/tray. **Keep Connected** is the Enter/Escape default; **Eject Now / Eject Device** explicitly requests safe removal of every listed partition/LUN. Empty/filtered results warn that other media may remain. Source identity, connection and topology are captured before copying and checked again for the one-use action. Connection changes, a new import and restart invalidate old permission. **Open Import Folder** checks the destination and rejects changed identities or redirected paths.

**Settings…** controls operation notifications (on initially) and debug logging (off initially). Notifications open the app for review and never eject. Windows may suppress balloons; pending choices remain in the window/tray. With notifications off, an opted-in completion prompt still appears as a native dialog. Foreground and notification-delivery acceptance remain pending. **View issue…** shows persisted failure details; Dismiss only acknowledges them and never retries. A later failure restores the warning icon. Debug logs remain in local app-data, capped at 1 MiB, and are never sent automatically.

**Import history…** lists the newest 20 completed media batches after source eject or restart. **Verify saved originals…** checks the saved destination identity, exact completion receipt and SHA-256 of every recorded saved original. It reads only recorded paths; unrelated files in the date folder are ignored. Changed destinations, receipts, copies and redirected paths are refused. Verification is cancellable and shares disk reservations with import/eject. History never grants eject permission. Its retention limit removes only records, leaving copies/receipts intact. Metadata-only and failed imports are excluded. History persistence errors are reported without disguising a successful copy as a failed import. Manual Quick Share is still pending.

- CFexpress can appear as NVMe/SSD storage. Folder evidence makes it a camera-media **candidate**, never confirmed CFexpress. Generic external SSDs remain visible; internal storage with DCIM stays internal.
- Volume GUID, filesystem serial, physical disk number/extents, PnP instance/devnode, removal target ancestry, and connection generation constrain actions. Disk numbers and drive letters alone are not identities. Session actions are not persisted across restart.
- The nearest removable PnP ancestor is considered; hub, PCI, ACPI, root, and docking boundaries are not removal targets. All known storage affected by that target participates in confirmation/reservations. The Windows API can remove multiple LUNs together; this differs from the Mac's sequential volume unmount.
- Unknown/spanning mappings, unavailable connection notifications, unreadable source identities, protected siblings, or incomplete inventory block operations. Empty/unsupported readers may conservatively block all operations until removed or successfully identified. Integrated readers without a suitable removable devnode may require Windows' own removal UI. No force-unmount fallback is implemented.
- Production imports reject same-disk partitions and different LUNs under the same removable target. Both source and destination disk groups are reserved. A device event conservatively cancels pending work, including unrelated device changes.
- Local drive-letter paths only, at most 240 characters per normalized path in this slice. UNC/device paths, alternate stream syntax, ambiguous components, symbolic links, directory junctions, and cloud-placeholder reparse points are rejected. Use an ordinary local destination outside OneDrive placeholders. Existing destination files are never overwritten; matching files are verified before reuse.
- Notifications, driver-reported ancestry, descriptor layouts, safe removal, handle rename/delete, filesystem durability, high-DPI layout, and tray behavior require runtime/hardware acceptance. Read-only CIM observations do not certify these.
- PTP/MTP-only cameras are unsupported. There is no automatic import/removal, original deletion, metadata cleaning, Trash recovery, Quick Share, hotkey, installer, updater, startup entry, packaging, Store submission, or public release. The optional post-import prompt always waits for an explicit eject choice.

## Architecture

`Models.cs` contains inventory models, classification, reservations, and eject policy; `Discovery.cs` provides read-only native inventory and connection generation; `Native.cs` holds P/Invoke and the Windows removal adapter; `SafePaths.cs` pins/revalidates file paths; `MediaSelection.cs` supplies frozen selection/package rules; `ImportLayout.cs` plans date folders and conflict groups; `Importer.cs` handles verified copy, physical-device guards, receipts and profiles; `ImportHistory.cs` persists exact completed batches and validates saved files with fresh destination guards; `ImportHistoryDialog.cs` supplies history browsing; `ImportDefaults.cs` supplies inherited/custom selection and persistence; `ImportDialogs.cs` supplies native editors; `ImportCompletion.cs` holds process-only completion authorization; `CompletionDialogs.cs` supplies completion/settings/issue views; `AppSettings.cs` supplies app preferences, issue state and local debug logging; `CardClassification.cs` supplies folder evidence; `ConnectionNotifications.cs` tracks per-instance generations; `BulkEject.cs` plans and verifies sequential grouped removal; `BulkEjectDialog.cs` supplies scrollable confirmation/results; `GlobalHotkey.cs` wraps the optional selected-letter shortcut; `Program.cs` supplies the manual tray/device flow. `IDiscovery`, `IEjectApi`, and `IImportGuard` make safety policy and file fixtures independent of real-device actions.

- [CM_NOTIFY_FILTER](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/ns-cfgmgr32-cm_notify_filter), [CM_Register_Notification](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_register_notification) and [CM_Unregister_Notification](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_unregister_notification): read-only instance event registration/lifetime; callbacks update counters and perform no scans/removal.
- [RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) and [UnregisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-unregisterhotkey): chosen-letter registration with no repeat and explicit release. - [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew), and [SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle): handle sharing, resolved-path checks, exclusive rename and owned-file cleanup.
- [Smart App Control signing](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control): trusted signing is the supported distribution path for protected computers; this local test blocker was resolved by Ryan.
