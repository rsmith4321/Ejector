# Easy Eject for Windows · prototype 0.1

Native C# / Windows Forms source for Windows 11 x64, using .NET Framework 4.8 and supported Windows storage/PnP APIs. This implementation is isolated from the Mac targets and website. The current prototype passes 1184 fixture/policy/native UI tests, native read-only enumeration, and a hidden-window notification smoke check. Real card/removal compatibility and foreground/DPI acceptance are pending. See [PROGRESS.md](PROGRESS.md) for exact evidence and [PARITY.md](PARITY.md) for the full-project parity scope and direct-download plan. The exact camera model, reader and destination remain to be confirmed; this is not a complete port yet. [SOURCE_AUDIT.md](SOURCE_AUDIT.md) records remaining functional and validation gaps found against the exact Mac contracts.

## Build and run

From the repository root in PowerShell:

```powershell
./Windows/build.ps1
./Windows/inspect-readonly.ps1
```

The build uses the installed `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, compiles app and test executable with `/warnaserror+ /platform:x64`, and places binaries/configuration under `%LOCALAPPDATA%\EasyEject\PrototypeBuild`, outside the OneDrive checkout. No SDK, NuGet download, installer, elevation, or startup registration is involved. A modern SDK project can be added later; this first slice uses the compiler already available on this laptop.

`-Test` runs 1184 cases. They use fake discovery/removal/startup-write adapters and disposable files under `%USERPROFILE%\.codex\EasyEjectFixtures\run-<id>`. Native Quick Share process/orchestration tests run copied versions of the project's own synthetic helper executable only inside those fixture folders; they verify process/descendant exit, held-file access, transaction ordering and owned log cleanup without actual encoding/decoding or calling media tools. Source and destination fixture directories share the host disk while the fake guard supplies two conceptual disk identities. Production imports always require different physical disks. Junction tests create junctions only within that fixture and do not change OS permissions. A configuration test writes/removes its own randomly identified fixture profile in the app's configuration storage. Default tests never invoke `CM_Request_Device_Eject` or install startup registration. `--inventory` reads native storage inventory, without a notification window or device operations. `--ui-smoke` constructs a hidden device window, registers disk and per-instance notifications with real shortcuts disabled, reads inventory and verifies system-eject policy; it briefly creates/disposes its tray icon but does not show a window or operate on devices. Read-only smoke/render windows exclude automatic import and profile edits. `--startup-inspect` reads only the app's own per-user login value, compares it before/after inspection and writes nothing. The separate PowerShell diagnostic uses OS CIM providers.

Smart App Control initially blocked an unsigned compiler probe. Ryan subsequently turned it off himself, after reviewing Microsoft instructions, and authorized continued testing. Ordinary executable launches now work. The agent did not change security policy, modify allowlists, install a trusted root, or use an alternate loader. Microsoft documents trusted code signing as the supported path for distributing an app with Smart App Control enabled; no signing account or credentials were used here.

## Use after runtime acceptance

The app opens a device window and adds a tray icon. Close hides the window; the tray's Quit exits when no operation is active. A session mutex prevents duplicate instances. Close also hides during an operation; tray Quit stays blocked until work and dialogs finish. Refresh performs read-only inventory. Device notifications refresh the list and invalidate pending actions. Automatic import starts off; explicitly enabled saved profiles may import on connection or app launch. Eject and sharing always require manual choices.

Select a device and choose **Safe eject…**. The confirmation names every known volume under the selected removal target, including sibling partitions and LUNs. No is the default. The service reserves affected physical disks, re-enumerates and compares identities/topology/connection generation, and requests Windows safe removal. Windows veto type, veto name, and CONFIGRET failures are shown without forced removal, retries, permissions changes, or broad hub ejection. Do not unplug after a failure.

The list groups camera candidates, emulator candidates, other external volumes, internal and protected Windows storage. Camera-folder evidence uses the eleven baseline root names. Emulator evidence needs two supported folders plus SD hardware; fixed/system storage and links never qualify. Generic NVMe with camera folders is only an unconfirmed camera candidate, never certified CFexpress. Card counts deduplicate partitions/LUNs under one removal device.

**Eject cards…** in the window/tray reviews all connected camera/emulator groups; Enter/Escape keeps them connected. Mixed/unclassified siblings and unknown/protected storage block the batch. The service reserves every confirmed disk first, removes one group at a time, verifies it absent, and stops on failure or changed peers. A final complete fresh inventory checks every previously removed target while reservations remain held, including on later failure/cancellation. Only still-absent devices remain listed as safe; reappeared devices or reused identities/mounts lose that claim, and unavailable/stale final inventory clears all provisional safe names. Earlier failure diagnostics remain visible. New cards are never added to an old confirmation; a new unrelated card at a different identity/location does not invalidate observed absence. Empty plans skip preparation and requests. The final result describes observed absence at that time. Per-instance notifications preserve unchanged peers across the batch's own removals and reject identical reconnects. Missing/faulted tracking blocks bulk removal; individually confirmed removal remains available with its ordinary connection guard.

Settings offer an optional **Ctrl + Alt + Shift + letter** shortcut, off initially, default E, with D/E/F/G/K/M/R/T/X choices. It opens the same fresh confirmation. Only the chosen key is registered; auto-repeat, busy operations/dialogs and stale queued messages are suppressed. Conflicts are reported without registering a fallback key. Native hotkey delivery and real multi-card removal are still pending acceptance.

**Automatically check for Windows releases** starts on, including older settings without that field; explicit off is preserved. In a configured release, checks wait for imports, ejects, scans and open dialogs, check signed metadata once after startup idle and then daily after each admitted attempt. Interrupted or failed checks do not retry every second. Installation remains manual and no system profile is sent. This development build has no approved Windows channel/publisher, reports checks unavailable and makes no release request. Turning this preference on does not enable automatic import, sharing or startup. Closing the device window leaves monitoring in the tray; Quit revokes pending check results.

**Launch at login** starts off. Explicitly changing it and saving registers/removes the app's own quoted command in the current user's Run key. Login launches into the tray; it remains separate from automatic import, although already-enabled profiles may import when monitoring starts. Saving starts no app or import. Opening/canceling Settings changes no registration. Foreign commands are left intact, stale edits refuse and a relocated copy requires **Use this copy at login** before Save. Windows may still disable or delay a registered app; use **Windows Startup apps…** to review its enablement. Easy Eject never overrides OS policy or enablement. Actual login/relocation acceptance remains pending; no startup entry was installed during development. See Microsoft's [Run-key contract](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys) and [Startup apps URI](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings).

Profiles normally live under local app-data. When launched by Codex's packaged host, Windows redirects the app's own configuration folder into that host's LocalCache. The profile store resolves this folder within local app-data and pins its canonical path. Source/destination media paths still reject redirection and all reparse points; there is no import-path exception for host virtualization.

Use **Import profile…** to choose a complete media folder or camera package on the selected volume and an existing destination on a different physical disk. Profiles offer **Use defaults / Use custom settings**, **Videos only**, **Include camera previews**, **Clean folder layout**, **Ask to eject after import**, optional **Permanently remove verified imported originals**, and independent **Recover device Trash**. Mac Trash owner selection belongs to each profile. Inherited choices are visible and disabled until custom settings is selected. Save validates paths/device identity and never starts copying. **Import defaults…** changes these choices for future imports using defaults; new profiles initially select Videos only with previews and clean layout, with eject prompting, original removal and Trash recovery off. Earlier prototype profiles remain custom all-media with previews, preserved paths and original retention unless explicitly switched. Forget profile removes only its saved choices after confirmation.

**Verified import…** uses the saved folders and freezes current choices. A scrollable review explains selection, source/destination and any permanent removal; Cancel is the Enter/Escape default. If no valid profile exists, setup comes first, followed by a separate import confirmation. Formatting or a changed identity requires setup again. Invalid saved settings are explained rather than preventing folder setup. Originals are retained by default; the device remains connected after import.

**Import automatically when connected** is available in shared defaults and custom profiles. It applies the same frozen media, preview, layout and acknowledged removal/recovery choices. Enabled enrolled sources run sequentially once per connection and at app launch, using the full verified copy engine and current device/disk guards. Saving a profile/defaults starts no import for already connected devices; reconnect or choose Verified import. A preflight wait may retry after a storage event, such as the destination arriving. Cancellation or failure during copying/removal does not retry automatically on the same source connection. Use a fresh manual action or reconnect. Completion may ask whether to eject; it never ejects or exports automatically.

Profiles bind the selected destination's volume/serial and physical disk instance/serial. Changed drives or reused letters refuse. Older profiles must have their destination explicitly selected again, or be saved with connected setup, before automatic import. A separately confirmed manual import can capture the missing binding. Re-selecting the destination in a profile is the explicit way to bind a replacement disk, even at the same path. History retains its own exact completed destination identity independently.

**Saved profiles…** in the window/tray reviews every saved device without requiring it to be connected. Give a device a recognizable name, change its inherited/custom choices or destination, or explicitly forget its profile. Device names remain independent of volume labels and appear in new history/completion entries. Connect the original device to change its media folder or select a new Mac Trash owner; an existing owner can be cleared offline. A changed destination requires a pinned local folder with a fresh different-disk check. Saving starts no import, and each import still validates the current device and both disks. Invalid records remain visible and intact for connected setup. Stale editors refuse to overwrite or forget newer choices/re-enrolled identities. Forget removes only configuration, preserving originals, copies, history and defaults.

Permanent original removal requires an explicit enabling acknowledgment in shared defaults or custom settings. Shared-default acknowledgment covers all devices following defaults, including future profiles. Changing Videos only to All media disables original removal and Trash recovery for review. After complete selected-batch/dependency verification, recognized imported originals and companions may be removed directly, skipping Trash. Unknown files, device indexes, excluded photos and skipped previews are retained; Videos only also retains non-video package support. Keep independent backups and originals for important media. Cameras with media databases may need camera-side recovery after outside deletion; camera erase/format after backup is preferable when unsure. Saving a choice starts no import/removal. Device Trash recovery is independently optional and starts off. Enabling requires its own acknowledgment; a per-profile Mac Trash owner must be selected explicitly. Every import reviews current owner scope. Recovered files preserve original names/packages; complete ordinary/Trash payload and restoration-record copies are held and verified before recognized payloads clear, followed by eligible Windows single-file restoration records. Skipped/unknown/index/other-owner data and Windows folder records remain. Counts distinguish ordinary original removal from Trash clearing. Interrupted clearing may leave an orphan Windows restoration record; retry currently refuses that orphan while retaining saved copies and audit evidence. A flushed, exclusively held removal-intent journal preserves exact complete-batch/file/device evidence before clearing begins; it grants no completion or eject authority. Read-only journal-bound interrupted-recovery review verifies complete copies, current device/owner/file identities and manifests; it grants no clearing/completion/eject authority. **Resume interrupted import…** selects the original device/profile and exact removal-intent.json, reviews the frozen choices/owner/permanent counts with Cancel as default, then revalidates and holds the complete batch through clearing and exclusive receipt publication. New removals and sources already absent are counted separately. Fresh manual retry also supports original-removal-only batches without reading Trash, or re-verification/completion after all scheduled sources are already absent. Exact completed history is restored; eject permission always comes from the current connection.

Each nonempty import uses a shared `YYYY-MM-DD` folder. Clean layout flattens ordinary media groups; whole conflict groups go under stable `Additional media/<fingerprint>` paths. Packages and unfamiliar files retain their selected folder/tree under `Camera originals/<fingerprint>`. Every import writes its own `.easy-eject-receipts/<id>/verified-import.json` and flushed `import-audit.log`. All-media selection copies regular files including unfamiliar extensions; Videos only uses conservative video/companion selection, protecting same-name still/movie pairs. Windows system-volume information and Recycle Bin folders are excluded. Partial camera-package selections are rejected; choose the complete package. Empty directories are not reproduced. This is verified file copying, not media conversion or universal camera-package certification.

The copy engine applies frozen videos/all-media and preview choices from the profile/default UI, with baseline still/movie, companion, proxy and structured-package rules. Seven file fixtures cover selection/package behavior; six further checks cover defaults/profile migration and frozen operation choices. Device indexes are backed up separately under `.easy-eject-metadata`, retained on source and distinguished from selected media in result/receipt. Matching saved files are SHA-256 verified and flushed before reuse; read-only saved files fail reuse safely. New files preserve camera modification dates and need free space greater than file size plus 1 GiB. Persistent last-20 history records exact saved files and destination identity. The other shared import options remain pending; see the full parity checklist.

Files are opened without following reparse points. Directory handles pin path components; source file handles deny concurrent write/delete. The importer checks source stamps, copies to exclusive private files with write-through/flush, hashes source and destination with SHA-256, re-reads source, and renames the held verified destination handle without replacing an existing file. It holds and verifies every source and saved dependency through any removal and exclusive completion publication. Read-only/system/offline/hard-linked removal candidates fail without changing protection. Each disposition has a durably flushed audit intent. Cancellation/failure retains saved copies and remaining originals, cleans only current held private work, and gives no completion authority. If removal had begun, the failure states the exact removed count, copy folder and audit path; retry is manual. Receipts and success text record actual removed entries/counts. Flush errors fail the operation; this does not prove a drive's power-loss behavior.

## Conservative limits and differences from Mac

**Clean & eject…** explicitly cleans the selected volume before requesting removal of the confirmed device/group. The off-default **Clean macOS metadata from cards before ejecting** setting needs an enabling acknowledgment and adds disclosed cleanup to future card, bulk/shortcut and post-import eject choices. Saving starts no work. Only regular `._*`, `.DS_Store`, `.apdisk` files and empty `__MACOSX` folders qualify; arbitrary contents, photos/recordings, Trash/system trees, links, system/offline items and hard-linked aliases are kept. Pinned paths, held handle deletion, volume/root identity checks, all-disk reservations and bulk root preflight protect each operation. Failure/cancellation stops the current eject; completed metadata removals remain applied and are counted. Real card cleanup/removal is still untested. The other-external-storage warning starts on; disabling its extra warning keeps the basic grouped removal confirmation.

If a saved recording folder is absent, Easy Eject reports no media only when repeated readable whole-card checks find no ordinary files; root device indexes alone may remain. It creates no recording folder or completion batch. A nonempty/unreadable card, redirected/file-shaped path, new recording or appearing/replaced selected ancestor refuses. Existing directory identities are checked before reads; held directory attribute handles alone do not guarantee that an empty directory cannot be renamed. Named baseline media/import evidence and exact scenarios still pending are listed in [REGRESSION_MAP.md](REGRESSION_MAP.md).

**Ask to eject after import** starts off. When enabled, completed imports appear in **Completed imports…** in the window/tray. **Keep Connected** is the Enter/Escape default; **Eject Now / Eject Device** explicitly requests safe removal of every listed partition/LUN. Empty/filtered results warn that other media may remain. Source identity, connection and topology are captured before copying and checked again for the one-use action. Connection changes, a new import and restart invalidate old permission. **Open Import Folder** checks the destination and rejects changed identities or redirected paths.

**Settings…** controls operation notifications (on initially) and debug logging (off initially). Notifications open the app for review and never eject. Windows may suppress balloons; pending choices remain in the window/tray. With notifications off, an opted-in completion prompt still appears as a native dialog. Foreground and notification-delivery acceptance remain pending. **View issue…** shows persisted failure details; Dismiss only acknowledges them and never retries. A later failure restores the warning icon. Debug logs remain in local app-data, capped at 1 MiB, and are never sent automatically.

The tray's **Help & Instructions…** explains the implemented actions; **About Easy Eject…** shows development version `0.1.0-dev` and current acceptance status. With debug logging enabled, **View debug log…** has explicit Refresh, Copy to Clipboard and Clear log actions. Copy uses the displayed text. Clear refuses a changed/new/replaced log until you refresh and review it, removes only that exact held private log, and keeps profiles, history and media intact. Hard-linked, offline/system, redirected or oversized logs are refused; read-only logs can be reviewed but their protections are never removed. Clipboard failures keep the displayed text. Enter/Escape closes these views. Opening them does not copy or clear anything, and they cannot interrupt active work/scans. Native foreground clipboard/scrolling and nondefault DPI acceptance remain pending; no Windows release/update channel is configured.

Tray status now shows the active phase in a disabled menu row and a bounded tooltip, with a busy icon and an attention badge for an earlier undismissed issue. Imports show measured hash/copy/check progress; 100% comes after receipt publication. Quick Share percentages refer to the **current encoded copy**; output validation stays busy and encoding at 100% does not complete the whole action. Scan/planning phases show their phase without a made-up percentage. Cancellation keeps a stopping indication and old queued callbacks cannot overwrite it or a final result. Final outcome and card counts remain available after refresh. Tray state remains available with notifications off. These native bindings and owned hidden icon/window renders pass tests; actual foreground tray behavior/themes/DPI and user clicks remain acceptance checks.

**Import history…** lists the newest 20 completed media batches after source eject or restart. **Verify saved originals…** checks the saved destination identity, exact completion receipt and SHA-256 of every recorded saved original. It reads only recorded paths; unrelated files in the date folder are ignored. Changed destinations, receipts, copies and redirected paths are refused. Verification is cancellable and shares disk reservations with import/eject. History never grants eject permission. Its retention limit removes only records, leaving copies/receipts intact. Metadata-only and failed imports are excluded. History persistence errors are reported without disguising a successful copy as a failed import. Quick Share appears for a selected retained batch only when its current saved device profile opts in. Each action asks size and LUT choice; enabling later offers earlier retained imports, and disabling or forgetting hides sharing while verification history stays available.

Quick Share's Luna identification, conversion recipe, probe/output/official-LUT rules, contained native runner and guarded export transaction are implemented/tested in source. Exact saved originals/receipt/tools stay held under fresh destination guards/reservations; outputs require probe/full-decode checks, identity/hash revalidation, flushes and non-replacing output/recipe receipt publication. Verified reuse, conflict names, partial publication counts, manual retry and private cleanup preserve existing copies and full-quality originals. Unknown/protected private data is retained with a warning. Profiles now have independent off-default manual sharing preferences, including preferred 1080p/4K and LUT choice; older profiles stay off and custom/default import mode changes preserve device preferences. An explicit Cancel-default size/LUT prompt is implemented/tested. Settings now offers explicit Quick Share tool/LUT setup. Save records executable paths and hashes without running tools, detects changed selections, and explicitly validates/copies only the user-supplied official LUT into local app data. Clearing selections preserves assets. Setup cancellation waits for the worker; late committed saves are reported honestly. Manual history/completion actions are now integrated. Each action freshly checks the exact retained batch, current opt-in, tool binding and destination, and asks size/LUT before work. Cancellation keeps retry history; failures preserve published copies and precise counts. Success from completion returns to a fresh Keep Connected/default eject choice only while its process entry remains current. Source absence and restart history never grant eject permission. FFmpeg, FFprobe and the manufacturer LUT are neither bundled nor installed automatically. Tool selection and each export are explicit. Positive official LUT copy and real conversion still require user-supplied tools/assets. Synthetic policy/native protocol helpers are not proof of actual encoding or full decoding.

- CFexpress can appear as NVMe/SSD storage. Folder evidence makes it a camera-media **candidate**, never confirmed CFexpress. Generic external SSDs remain visible; internal storage with DCIM stays internal.
- Volume GUID, filesystem serial, physical disk number/extents, PnP instance/devnode, removal target ancestry, and connection generation constrain actions. Disk numbers and drive letters alone are not identities. Session actions are not persisted across restart.
- The nearest removable PnP ancestor is considered; hub, PCI, ACPI, root, and docking boundaries are not removal targets. All known storage affected by that target participates in confirmation/reservations. The Windows API can remove multiple LUNs together; this differs from the Mac's sequential volume unmount.
- Unknown/spanning mappings, unavailable connection notifications, unreadable source identities, protected siblings, or incomplete inventory block operations. Empty/unsupported readers may conservatively block all operations until removed or successfully identified. Integrated readers without a suitable removable devnode may require Windows' own removal UI. No force-unmount fallback is implemented.
- Production imports reject same-disk partitions and different LUNs under the same removable target. Both source and destination disk groups are reserved. A device event conservatively cancels pending work, including unrelated device changes.
- Local drive-letter paths only, at most 240 characters per normalized path in this slice. UNC/device paths, alternate stream syntax, ambiguous components, symbolic links, directory junctions, and cloud-placeholder reparse points are rejected. Use an ordinary local destination outside OneDrive placeholders. Existing destination files are never overwritten; matching files are verified before reuse.
- Notifications, driver-reported ancestry, descriptor layouts, safe removal, handle rename/delete, filesystem durability, high-DPI layout, and tray behavior require runtime/hardware acceptance. Read-only CIM observations do not certify these.
- PTP/MTP-only cameras are unsupported. Quick Share actual-codec/official-LUT and foreground acceptance remain pending. Manual installation/update/rollback guidance is available from the tray. Read-only extracted-folder package validation is implemented in source with managed/resource identity agreement; held ZIP contents authentication and exact extracted-package binding are implemented; signed channel record/exact archive binding and bounded HTTPS metadata discovery and optional persistent user-bound replay restrictions plus guarded automatic-check settings/runtime lifetime are implemented in source; manual metadata/ZIP/extracted-folder review UI and owned cancellation/lifetime are implemented; explicit replay recovery/migration and actual trusted artifacts, signed distribution packaging and public release remain pending; see [DISTRIBUTION.md](DISTRIBUTION.md). Opt-in automatic import and login registration are implemented in source; hardware events and actual login acceptance remain pending. Original removal is optional and acknowledged; actual card-filesystem behavior remains untested. Eject and metadata cleanup require explicit reviewed actions; the optional post-import prompt waits for a choice. The global shortcut starts off and opens the same review. Store submission is out of scope.

## Architecture

`Models.cs` contains inventory models, classification, reservations, and eject policy; `Discovery.cs` provides read-only native inventory and connection generation; `Native.cs` holds P/Invoke and the Windows removal adapter; `SafePaths.cs` pins/revalidates file paths; `MediaSelection.cs` supplies frozen selection/package rules; `ImportLayout.cs` plans date folders and conflict groups; `Importer.cs` handles verified copy, physical-device guards, receipts and profiles; `ImportHistory.cs` persists exact completed batches and validates saved files with fresh destination guards; `ImportHistoryDialog.cs` supplies history browsing; `ImportDefaults.cs` supplies inherited/custom selection and persistence; `ImportDialogs.cs` supplies native editors; `ImportCompletion.cs` holds process-only completion authorization; `CompletionDialogs.cs` supplies completion/settings/issue views; `AppSettings.cs` supplies app preferences and issue state; `DebugLog.cs` supplies private snapshot-bound diagnostics; `ApplicationInformation.cs` supplies development version metadata and Help/About views; `ManualInstallation.cs` supplies guarded Windows installation/update/rollback guidance and explicit folder views; `WindowsAuthenticode.cs` supplies held-file cached native trust and explicit publisher binding; `WindowsManifestTrust.cs` supplies exact-byte detached CMS authentication, immutable metadata snapshots and current cached native certificate trust; `WindowsChannelOffer.cs` supplies signed Windows channel records, exact archive/release binding, UTC freshness, numeric comparison and process-only replay protection (no configured production endpoint); `WindowsChannelDiscovery.cs` supplies bounded metadata/signature GETs and guarded asynchronous authentication (fake HTTP proof, no configured app check); `WindowsChannelReplay.cs` supplies explicitly composed CurrentUser-protected replay restrictions and exact prior-state publication checks (retained-state restart protection, no cached offer/install authority); `WindowsUpdateCoordinator.cs` supplies owned revocable check scopes, configured-only startup/daily scheduling, automatic-check preferences and one-use foreground delivery; `WindowsReleaseReview.cs` supplies explicit metadata/selected-ZIP/extracted-folder verification, owned modal/check scope, manual retry and bounded read-only results; `WindowsArchiveReview.cs` supplies held bounded ZIP contents/CRC/signed-payload validation and independent extracted-package binding; `WindowsPackageReview.cs` with `WindowsReleaseManifest.cs`, `WindowsExecutableIdentity.cs`, `WindowsManagedIdentity.cs` and `WindowsPackageStreams.cs` supplies held folder/schema/PE-resource/managed-identity/config/hash validation (foreground acceptance and explicit replay recovery/migration remain pending); `CardClassification.cs` supplies folder evidence; `ConnectionNotifications.cs` tracks per-instance generations; `BulkEject.cs` plans and verifies sequential grouped removal; `BulkEjectDialog.cs` supplies scrollable confirmation/results;
