# Modern optional notification delivery

All four modern balloon paths now use `TrayNotificationDelivery`: import/completion, manual safe removal, other-device removal and accepted release notices. A shell delivery exception returns a separate presentation warning; it does not replace the terminal result, skip the subsequent manual result dialog, escape the other-device callback or reclassify an accepted release as a failed check. The other-device result remains visible and its exact review can release the primary completion wait normally. Disabled notifications and a closed app do not call the delivery adapter. Notification clicks retain the existing open-app behavior and grant no operation authority.

Headings and bodies respect the existing shell limits of 63/255 UTF-16 code units without splitting a surrogate pair. Success/cancellation use the information icon; a refused other-device removal uses the warning icon. Delivery has no automatic retry. This does not prove that Windows displays an accepted balloon or that notification suppression is observable.
