# Modern on-disk runtime configuration contract

`ModernWindowsRuntimeConfiguration` is an additional read-only layer after [held package content review](PACKAGE_CONTENT_CONTRACT.md). It does not approve an installable package or enable ModernProductionChannel. Apphost/managed identity, actual component versions, dependencies, archive ownership and independent publisher/channel approval remain required.

The current self-contained SDK output has one `runtimeOptions` object containing `tfm`, `includedFrameworks` and `configProperties`. This application's reviewed policy requires `net10.0`, exactly Microsoft.NETCore.App and Microsoft.WindowsDesktop.App, and both versions equal to the authenticated release's DotNet declaration. Framework order and JSON whitespace are harmless. The three observed properties must all be boolean false: metadata updater support, unsafe BinaryFormatter serialization and Windows UI XAML projections. This is a deliberately narrow application policy, not a general runtimeconfig schema or a promise about external process/environment settings. The [.NET SDK runtime configuration specification](https://github.com/dotnet/sdk/blob/main/documentation/specs/runtime-configuration-file.md) documents host options including shared frameworks, roll-forward and additional probing paths; these are outside this application's reviewed on-disk policy.

Parsing uses a cloned, strictly decoded UTF-8/no-BOM snapshot bounded at 8192 bytes. Unknown, missing, duplicate (including escaped equivalent names), typed/substituted fields, wrong framework families/versions, extra launch/probing/roll-forward settings, enabled/extra properties, incomplete/trailing documents and excessive bytes refuse. An authenticated inventory containing EasyEject.Modern.runtimeconfig.dev.json also refuses, including case aliases: the SDK documents development configuration as an additional/override source, so validating only the main JSON is insufficient for this policy. Existing strict JSON framing/type/field helpers remain unchanged. No runtime/assembly/host is asked to consume the candidate configuration.

`Require` receives an existing content review, refreshes held files/apphost/manifest trust, inspects the held stream within its byte bound, checks cancellation during reading, validates the configuration against that same immutable release, and refreshes trust/content again before returning. The content owner retains its complete native path/file holds until disposal; this layer does not extract, load, execute, install, register startup, change settings or clean anything. Configuration success alone grants no launch, installation or device authority.

Eleven generated/fake-trust groups cover companion development-file refusal, valid declarations/order/whitespace, both version bindings, extra launch fields, missing/duplicate/foreign/typed frameworks, required false properties, escaped duplicate names/framing/types, UTF-8/BOM/size/authenticated metadata, held-content/no-write/unchanged bytes, independently authenticated unsupported policy/fresh retry, and cancellation/refreshed trust/disposal/hold release. The actual external SDK sample is separately scoped; no fake signer is an approved publisher.
