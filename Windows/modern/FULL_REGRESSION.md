# Full runtime regression on .NET 10

The full finish goal requires the existing software contracts on the actual new runtime, alongside the selected modern-controller cases and actual WinUI acceptance. This harness runs all default Windows/tests sources against the same EasyEject.Runtime project used by WinUI, without recompiling a substitute copy of production policy into the test assembly. InternalsVisibleTo permits the harness to exercise existing internal contracts.

From PowerShell:

```powershell
./Windows/modern/build.ps1 -Test -FullTest -BuildRoot C:/Users/rsmit/.codex/EasyEjectBuildTools/ModernFullRegression
```

`-Test` runs the selected modern controller/draft cases; `-FullTest` runs the entire existing default suite. Counts remain separate because some contracts overlap. Both use warnings as errors, the pinned private SDK/cache and output outside OneDrive. The build refuses to overwrite an app or contract runner still executing from its output directory. SDK certificate generation/telemetry are disabled for its process, with prior environment restored afterward. No tool installation or system setting change is performed.

The default suite covers import selection/copy/reuse/receipts/history, device/connection/reservation policy with fake eject, optional original removal and owner-aware Trash/recovery/resume on disposable files, saved/default/profile configuration and native directory ownership, lifecycle/startup/reopen/tray/dialog policy, settings/issue/debug/layout, manual sharing/probe/decode/transaction/cancellation policy, guarded supplied-tool configuration/native process containment, and update/replay/recovery/authentication/package/archive policy. It does not invoke the opt-in real-media-tool harness, optional allocated >2 GiB fixture or native inventory command. No physical device is ejected or altered.

The production storage-root roundtrip case creates one nonce-named fake profile in the app-data configuration root, verifies its roundtrip and deletes only that exact generated file. It does not change a connected device profile or defaults/settings. Compare known live JSON inventories before/after; other generated data is confined to owned EasyEjectFixtures directories.

Framework binaries built alongside the suite serve two existing fixture purposes. The unsigned EasyEject.Windows.exe/config are read-only inputs to the existing Framework 4.8 release/package-policy tests, not a proposed modern release package. The owned Framework test executable supplies synthetic native subprocess protocols, including probe/encode/decode-shaped responses; it is not FFmpeg or a real media decoder. The native process orchestrator under test is the actual .NET 10 runtime implementation. Cold history and session-reopening children execute the .NET 10 harness itself. These fixtures do not prove modern artifact signing, codecs, official LUT conversion or direct distribution.

Existing hidden Forms layout tests use the classic SystemAware context. The .NET test entry point sets its own DPI context before creating handles, following [Microsoft's WFO0003 guidance](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/compiler-messages/wfo0003). WinUI keeps its separate PerMonitorV2 manifest. No display/scaling setting is changed. Hidden Forms tests do not establish actual modern WinUI rendering, input, picker, notification, tray or modal/worker acceptance.
