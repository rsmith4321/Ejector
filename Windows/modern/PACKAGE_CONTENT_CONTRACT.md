# Modern extracted-folder content and ownership review

`ModernWindowsPackageContentReview` is the read-only file/content layer following [the authenticated manifest/index contract](RELEASE_MANIFEST_CONTRACT.md). It is deliberately separate from completed package identity or installation approval. ModernProductionChannel remains null. There is no extraction, execution, DLL/assembly loading, installation, startup registration, tool download, cleanup or public release.

Before either externally supplied trust callback, the review holds the selected root/ancestors, captures every nested directory and opens/hashes every actual file without write/delete sharing. Paths, per-file/aggregate sizes and directory/file counts are bounded. Each branch retains its own ancestor frame through enumeration; all original frames are checked before and after coalescing into the final directory lease. Empty-directory replacement therefore cannot be adopted by a later callback. Native file identity/stamps/final paths, single-link policy and complete hashes remain checked. The same existing alternate-stream policy refuses unlisted data while retaining bounded Zone.Identifier download metadata, which conveys no trust.

The actual apphost is independently reviewed against the supplied approved publisher. Manifest verification must return the exact held envelope/signature snapshot and exact apphost signing certificate. The authenticated index must match actual file names, lengths and SHA-256 values. The complete tree must contain exactly those files plus the three metadata files, with only their necessary parent directories and exact recorded spelling. Extras, missing files, casing changes, unknown streams, aliases, redirection/offline objects or late replacements refuse. Later revalidation rehashes held files and refreshes apphost/manifest trust; a guarded stream inspection checks ownership before and after the callback. Failure/cancellation/disposal release holds and never modify or clean package contents.

Actual dependency/runtime-component identity and native startup sufficiency are **additional required layers**. Separate [on-disk runtime configuration](RUNTIME_CONFIGURATION_CONTRACT.md), [managed PE/metadata identity](MANAGED_IDENTITY_CONTRACT.md) and [native apphost layout/resources](APPHOST_IDENTITY_CONTRACT.md) layers validate their held files, but are not integrated installable-package approval or native code-body verification. This content type is not a trusted installable package result. The source contains no configured production publisher/channel and never treats a fixture signer as one.
