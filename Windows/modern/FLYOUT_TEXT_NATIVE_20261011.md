# Native flyout status layout · October 11, 2026

The previous [theme inspection](THEME_NATIVE_20261011.md) suspected vertical status-text clipping from a bounded screenshot. Native measurements **do not confirm that defect**: the original production status fits its auto-sized header, has no reported trimming and does not overlap the device viewport. Production typography/layout is unchanged. Pixel readability and broader display acceptance remain open; no cause for the earlier screenshot appearance is inferred.

An engineering-only regression now creates the real flyout with generated devices and no action callbacks, exercises short and deliberately wrapped statuses in Light/Dark, records native content-position rectangles and checks their bounds against the text/header/viewport. It also retains the footer/work-area assertions. The test tolerates at most one physical pixel of fractional layout rounding. It restores the original status in finally and closes its temporary window. All new methods are excluded from normal builds; the production static theme-resource contract remains unchanged.

The probe uses the documented [TextPointer.GetCharacterRect](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.documents.textpointer.getcharacterrect?view=windows-app-sdk-2.0) API for layout content bounds. These rectangles are not a pixel-ink/font-readability test. Returned zero-width character edges and text-element offsets are retained without representing them as a count of distinct glyphs.
