## Behavior

Warnings from import/resume/history/sharing/removal, invalid automatic profiles/configuration, shortcut and discovery failures retain bounded explanations independently of notification enablement. Existing AppIssue storage is reused. Missing issue state starts empty; an invalid/unreadable saved issue is retained, with persistence disabled rather than silently replacing it. Successful operation results resolve the current issue through guarded configuration publication; failure keeps its explanation available. Ordinary cancellation does not acknowledge or retry an earlier issue. Repeated discovery errors in one unchanged epoch are not repeatedly published. Idle attention uses the owned warning icon/tooltip; active work keeps its busy icon. Candidate card counts deduplicate physical removal groups and use physical-disk fallback identifiers.

View issue opens a scrolling Close-default explanation and offers Dismiss only for an undismissed issue. The one-use IssueReview captures message/time/dismissal plus an in-memory revision. Changed fields or a later identical-payload failure revoke acknowledgement. A saving review refuses cancellation/duplicate workers; its saver receives a copy. A failed save consumes the review and keeps attention; an applied write followed by failure remains an uncertain outcome requiring a fresh persisted-state review. A later failure during save retains its newer explanation/attention. Dismiss never retries any import, export or removal, and acknowledged explanations remain viewable. The revision is not serialized, preserving the existing JSON schema. Issue acknowledgement binds the live state; persisted snapshots and uncertain-save reopening are now connected in source 886f0fa; see [ISSUE_RECOVERY.md](ISSUE_RECOVERY.md) for the separate software evidence and pending foreground acceptance.

Debug log is visible only while saved debug logging is enabled. Opening loads the exact private log, but does not copy, clear or refresh it automatically. Refresh explicitly replaces the displayed snapshot. Copy uses only displayed text on the UI thread; tests use a fake clipboard callback. Clear delegates to the existing exclusive, single-link, hash/stamp-bound DebugLog.Clear and touches only debug.log. Changed/replaced/read-only/oversized/redirected/protected or concurrently held files retain the existing refusal policy. A failed clear attempt is consumed until explicit Refresh, and successful clearing followed by failed readback reports that deletion already happened while retaining the displayed evidence. Refresh/clipboard failures preserve text; a missing log has no Copy/Clear action. Close and other actions refuse while a worker owns the view. ContentDialog closing is cancelled during work; if XAML presentation fails, the owner remains held until the exact file worker ends, with late rendering disabled after closure.

Help/About are Close-default scrolling, selectable text and never launch tools or actions. Modern About names the actual .NET 10/WinUI 3 development runtime/version; classic About remains Framework 4.8. Modern Help points to the actual Quick Share tools action, manual 1080p/4K/LUT choices, original preservation, exact last-20 history and explicit login Save/Cancel. It reports updates unavailable rather than advertising the still-unconnected modern installation/release view. The dialogs use the existing review/busy/close/Quit rules and explicit visible-XAML readiness. [Microsoft's ContentDialog reference](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.controls.contentdialog?view=windows-app-sdk-2.0) documents XamlRoot and cancellable closing; actual foreground behavior remains an acceptance gate.
