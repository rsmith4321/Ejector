# Modern native launcher identity

`ModernWindowsAppHostIdentity` is a read-only layer after [held package content review](PACKAGE_CONTENT_CONTRACT.md), separate from [managed identity](MANAGED_IDENTITY_CONTRACT.md). It refreshes complete content/apphost/manifest trust, inspects the held EasyEject.Modern.exe, binds the native resource API's path to that held handle's final path, and refreshes ownership/trust again before returning. It does not execute the launcher, load a candidate module, approve installation or configure ModernProductionChannel.

The launcher must be a bounded x64 PE32+ GUI executable with no CLR directory, uniquely mapped readable executable native entry-point bytes and nonoverlapping bounded raw/RVA section ranges. The current reviewed .NET 10 Windows template stores one bundle locator followed by the 512-byte default .NET search slot and the 1,025-byte application slot in readable/writable/non-executable initialized data. The bundle offset must be zero; search configuration must retain the exact default placeholder/padding; application binding must be exactly EasyEject.Modern.dll followed by NUL padding. Missing/duplicate/planted locators, alternate application paths, nonzero bundle/search choices, changed slot padding or unsupported mappings refuse.

This intentionally checks the current reviewed template layout rather than claiming a general apphost parser. Microsoft's [.NET apphost writer](https://github.com/dotnet/runtime/blob/v10.0.0/src/installer/managed/Microsoft.NET.HostModel/AppHost/HostWriter.cs), [native application binding](https://github.com/dotnet/runtime/blob/v10.0.0/src/native/corehost/corehost.cpp) and [bundle marker](https://github.com/dotnet/runtime/blob/v10.0.0/src/native/corehost/apphost/bundle_marker.cpp) supply the slot/marker contracts. Contiguous placement and PE data-section characteristics were independently observed in our retained local build. A future SDK/runtime layout change needs explicit review; finding a DLL name somewhere in a file is insufficient. The default search policy does not constrain external process/environment configuration.

Native ProductName/FileDescription must be Easy Eject/Easy Eject for Windows. OriginalFilename/InternalName are EasyEject.Modern.dll, matching SDK resource copying from the managed WinExe. FileVersion/ProductVersion must both match the authenticated canonical stable four-part release. The ordinary development artifact's ProductVersion 0.1.0-dev correctly refuses stable release approval. Native layout/resources are declarations, not verification of code bodies or proof of startup; independently approved publisher/content, complete dependencies/components and actual startup remain mandatory.
