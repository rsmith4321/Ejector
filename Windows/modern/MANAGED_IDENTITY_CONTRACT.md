# Modern managed application identity

`ModernWindowsManagedApplicationIdentity` adds read-only PE/metadata identity after [held package content review](PACKAGE_CONTENT_CONTRACT.md). It refreshes held content/apphost/manifest trust before and after inspecting EasyEject.Modern.dll and binds identity to that same authenticated release version. It grants no execution, installation, device or channel authority; ModernProductionChannel remains null.

The bounded PE reader requires x64 PE32+, GUI executable (not DLL flag), supported IL-only CLR flags and uniquely mapped, bounded BSJB metadata. The modern path additionally requires a nonzero CLR MethodDef entry-point token. System rometadata.dll reads a pinned snapshot read-only/no-transform; candidate assemblies/dependencies are not loaded, attributes are not constructed and candidate IL is not executed.

Assembly name must be EasyEject.Modern, title Easy Eject for Windows and product Easy Eject. Assembly, file and informational versions all equal the authenticated canonical stable four-part version. Duplicate/missing/malformed identity attributes refuse. External constructors bind to neutral System.Runtime 10.0.0.0, public-key token b03f5f7f11d50a3a, with the supported constructor signature. Classic mscorlib 4.0.0.0 policy remains separate with no fallback.

The entry point must resolve to private static HideBySig Main, managed IL implementation, nonzero RVA and void Main(string[]) signature, owned by EasyEject.Modern.Program. This verifies metadata identity and the declared entry-point contract, not method bodies, startup, native apphost binding/resources, dependencies or other components. Those remain independent required layers.
