## Manual Quick Share contract

- Per-device offer starts off and is independent of shared import defaults. Enabling after import makes eligible history visible; disabling hides the action. Import never starts export. Each action explicitly chooses 1080p/4K and LUT on/off; BT.709 tags cannot identify I-Log.
- Persist only the last 20 completed batches: exact verified original paths/SHA-256, device/profile, destination volume/identity and date. History survives source eject/restart. It never restores connection-bound eject authority and never rescans earlier destination folders for candidate clips.
- Restrict current conversion to `VID_*.mp4` with embedded Luna Ultra/Pro identity, preserving the Mac tail-identity rule. Reject changed originals/destination and HDR/Dolby Vision. Neither FFmpeg/FFprobe nor the manufacturer LUT is bundled. The user supplies the official `Luna_I-Log_to_Rec709_BT1886_s33_v2.cube`; validate the baseline official SHA-256 `e3e5c3ab4ca7c166f3ebb740b45ed8cbce649b0c18dca9d5661754c53b9ee17d`.
- Preserve landscape/portrait framing with even dimensions, no upscale/crop/stretch; cap 30 fps; H.264 at 8 Mb/s (1080p) or 24 Mb/s (4K), stereo AAC 160 kb/s, SDR BT.709 output. Replace VideoToolbox with an explicitly validated Windows encoder/fallback while preserving the recipe's behavior.
- Probe dimensions/duration/audio/color, compare duration within 0.25 s and fully decode video/audio before publication. Recheck originals, flush output, exclusively publish, and write recipe/source/LUT/export hashes. Hash-verified receipt reuse and safe conflict names preserve previous exports. Cancel/timeout cleans only current private work and retains completed copies. Failures retain retry history and report originals unchanged; success returns to a fresh eject choice when invoked there, never ejects automatically.

## Direct download and signing

The local executable is an **unsigned prototype**. Smart App Control initially blocked it (Code Integrity events 3077/3033/3118); Ryan changed Smart App Control himself and normal tests now run. The agent did not disable or bypass security. This resolved local blocker does not prove an unsigned public download will run on protected computers.

Microsoft documents trusted-provider certificates and recommends [Artifact Signing](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/code-signing-for-smart-app-control). Use **Public Trust** for public Windows downloads; Private Trust and Public Trust Test are not publicly trusted. A trusted-provider certificate used with SignTool is another supported path. No signing identity/certificate/credentials were supplied or used here, so signing remains pending. [Microsoft trust models](https://learn.microsoft.com/en-us/azure/artifact-signing/concept-trust-models).

Artifact Signing needs an Azure subscription, tenant, identity validation and certificate profile. Individual public signing currently requires a US/Canada location and matching individual billing/identity information. Ryan's eligibility/accounts have not been verified. Review this after local proof; no accounts or paid services are created here. [Microsoft setup requirements](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart).

Proposed initial artifact: versioned ZIP with signed x64 app/config, usage/release notes and SHA-256 checksums on the project's official release channel after authorization. Extract into an ordinary local user folder and launch, with no elevation or auto-start by default; settings remain in app-data. Initial updates are manual: finish work and quit, download/verify the replacement, retain the previous version for rollback, relaunch. Uninstall removes the extracted app; profile deletion is a separate choice. Confirm final artifact/channel after hardware/runtime proof. Nothing is published here.
